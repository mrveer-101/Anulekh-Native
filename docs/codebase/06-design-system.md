# 6. Design system

The app is **light-mode only** (dark mode was removed; `app.json` → `"userInterfaceStyle": "light"`).

## Portal themes (`core/portalTheme.ts`)

Each portal has one palette, so every tab looks consistent:

| Token | Purpose | Student (blue) | Scribe (green) |
|---|---|---|---|
| `primary` | icons, borders, status strips | `#2563eb` | `#16a34a` |
| `accentText` | coloured text on white | `#1d4ed8` | `#15803d` |
| `solid` | fills with white text (contrast-safe) | `#2563eb` | `#15803d` |
| `soft` / `softBorder` | tinted chips, badges, call/chat buttons | 8 % / 20 % blue | 8 % / 22 % green |
| `cardBorder`, `shadow` | white cards with tinted border + coloured shadow | | |
| `page` + `pageGradient` | soft page background (+ colour `orb`) | blue → lavender → white | mint → white |
| `hero` + `heroGradient` | gradient header banners (Home, Account) | | |
| `buttonGradient` | primary action buttons | blue → indigo | dark → mid green |

`PORTAL_THEMES.scribeOrange` is an alternative scribe palette; switch with one line (`SCRIBE_THEME`).
`ScribeHomeView` additionally has a local `ACCENT_PALETTES` (green/orange) for its own accents.

`gradient(css)` returns `{ backgroundImage }` on web and `{ experimental_backgroundImage }` on native —
always pair it with a solid `backgroundColor` fallback.

## Recurring patterns

* **Status strip** — a 4 px coloured bar on the left edge of request/plan/application cards
  (red = SOS, green = confirmed/open, amber = applied/pending, pink = invited/private, blue = pending student request).
* **Section titles** — 30 px tinted icon badge + uppercase/bold title.
* **Header buttons** (intro) — ≥ 44 px touch targets, solid light tints (blue language/back, orange skip).
* **Inputs** — focused field gets an accent border, white background and tinted icon; the browser focus
  ring is hidden on web (`outlineStyle: 'none'`) because the border shows focus.
* **Icons instead of emoji** — emoji don't render reliably on every device; use Feather / Ionicons /
  FontAwesome5 icons.

## Start-up / splash (`components/ui/BrandSplash.tsx`)

1. **Native splash** (`app.json` → `expo-splash-screen`): paper `#FBF8F3` + rounded logo tile
   (`assets/images/splash-icon.png`, 152 dp, sized to fit Android 12's circular mask). iOS shows the full
   colourful image (`splash-full.png`).
2. **Overlay** (`AnimatedSplashOverlay` → `SplashOverlay`): paper texture + blue/orange/green clouds
   (`splash-background.jpg`), logo and title; fades into the app after ~1.4 s.
3. **Loading screen** (`app/index.tsx`): the same visuals while the session is checked.

## Icon fonts

Icons come from `@expo/vector-icons` (Feather, Ionicons, FontAwesome5 only). For reliable web deploys the
fonts are embedded as base64 in `src/vector-fonts-b64.css`, generated by `npm run build:fonts` under the
exact family names the library registers (`feather`, `ionicons`, `FontAwesome5Free-*`). Do not add other
`@font-face` rules for these families — mismatched versions break glyphs.

## Motion

React Native Reanimated, always guarded by `useReducedMotion()` (no motion when the OS "Reduce Motion"
setting is on): staggered `FadeInDown` entrances, `ZoomIn` pops for icons/numbers, spring press feedback,
sliding switches. Looping animations pause while their tab is hidden (`useTabActive()`).

## Accessibility

Target users include visually-impaired students, so: meaningful `accessibilityLabel`/`accessibilityRole`
on interactive elements, `aria-checked`/`aria-selected` for switches and chips (react-native-web ignores
`accessibilityState`), errors announced with `announceForAccessibility()`, decorative icons hidden from
screen readers, ≥ 44 px touch targets for primary controls.
